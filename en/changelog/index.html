    Changelog¶

    Scope of this page

    Recent releases are documented here in English. Older entries (v0.1.73 and earlier) exist only in the Chinese changelog, which is the complete history.

    v0.1.82 (2026-07-27)¶

    Features¶

    • The documentation site was rewritten, and an English edition added. The eight pages published until now were written for the first release and had not followed the product for more than three months. They described building with CMake + Ninja + arm-gcc, running on Windows/macOS/Linux, cloning the source, and pasting in your own API key — whereas EmbAI is a Windows desktop application whose firmware is compiled only by Keil MDK, installed from an installer, with cloud accounts. They also referenced things that do not exist in the code at all (an EMBAI_PORT variable, ~/.embai/settings.json, six invented AI tool names, three non-existent scripts) and contradicted themselves on endpoint paths. Everything is now rewritten from the code: a nine-chapter user guide organised by feature (projects, editor, build & flash, debugging, serial & dashboard, AI assistant, virtual display, schematics & knowledge, account & credits), Chinese at the original address and English under /en/ with a language switcher, styled to match the EmbAI brand. The architecture, development and API reference pages were retired — they had drifted badly out of date and were written for maintainers rather than users. The documentation cards in Help & feedback point at the new chapters.

    Fixes¶

    • "Attach screenshot" was capturing the feedback panel itself. The capture takes the whole window, and the Help & feedback panel was sitting on top of it as an overlay with a dimming backdrop — so every attachment showed the feedback panel over a darkened background, hiding the AI assistant or editor state the user actually wanted to show. The panel is now hidden for the instant of the capture and restored immediately, with the text you have written, your checkbox choices and the fetched diagnostics all preserved.
    • Made it clear that the GitHub route pre-fills rather than submits. The button used to read "or file an issue on GitHub", sitting right under the "Submit feedback" button that really does send — but GitHub does not let an application file an issue on your behalf, so this path can only open a pre-filled form in your browser that you still have to submit yourself. The button text and the message shown after clicking now say so.
    • Fixed nothing happening when the GitHub button was pressed with a long body. The length limit on the pre-filled link was measured in characters, but Chinese is percent-encoded as UTF-8 in a URL at nine characters per glyph — a 1,200-character body produced an 11,431 character link, far past the system limit, so the browser never opened and nothing was reported. The limit is now applied to the actual link length (bodies up to roughly 145 Chinese characters are unaffected); longer ones pre-fill the beginning and say the full text is still in the input box. Failures to open the browser are now reported instead of ignored.
    • Screenshot failures are now reported instead of silently doing nothing.

    v0.1.81 (2026-07-25)¶

    Fixes¶

    • Help & feedback went from mock-up to a real feature. Previously all 12 links in the panel were dead placeholders, the video-tutorial durations and view counts were invented, "attach screenshot" was a toggle that sent nothing, and pressing "Submit feedback" only displayed "submitted successfully" — nothing was actually sent. Now the quick-start and documentation links point at the real online docs; feedback is genuinely submitted and visible server-side; failures report the actual reason and offer GitHub Issues instead of pretending to succeed; "attach screenshot" really captures the current window; and before submitting you are shown the version, OS and backend log tail that will be attached, with the log optional. The two non-existent entries (video tutorials and Discord) were removed.

    v0.1.80 (2026-07-25)¶

    Fixes¶

    • Tightened the capability boundary and timeout handling of AI delegated exploration. Sub-agents are now restricted to exactly three tools (list directory, search, read file) and no longer silently gain reach when new read-only tools are added elsewhere. Startup, execution, cancellation and cleanup share one five-minute budget, and a timeout returns the partial findings rather than nothing. Delegated exploration is no longer accounted as a write operation, so it neither holds the write lock nor triggers the "previous write result unknown" retry guard.
    • Removed AI tool switches that could not be turned off. The tool list now shows only tools you can actually enable or disable, omitting three built-ins whose switches had no effect.
    • Question cards could be lost when a turn was cancelled. If a turn was cancelled at the exact moment the AI asked you something, the question card is now still written to the transcript and survives a refresh.

    v0.1.79 (2026-07-24)¶

    Fixes¶

    • Reinstalling or updating sometimes required signing in again before models appeared. When the saved sign-in token had already expired at cold start, the local backend did not return 401, so the front end never refreshed it — but forwarding the expired token to the cloud to fetch the model list was rejected, leaving the list empty. Expired tokens are now refreshed before fetching, the model list is re-fetched after a successful refresh, and a failed cloud fetch retries after refreshing. No manual re-login needed.

    v0.1.78 (2026-07-24)¶

    Fixes¶

    • Fixed a crash loop with custom models in the packaged build. When the local encryption key changed and a saved custom-model API key could no longer be decrypted, the backend crashed and retried endlessly. It now reports clearly that the key cannot be decrypted and asks you to re-enter it in settings, while remaining fully usable — you can switch models and stop the turn. The local encryption key is no longer silently regenerated when it fails to load (which orphaned every stored key). A dropped AI connection now backs off exponentially and stops after repeated failures with a "Retry connection" button, instead of reconnecting every two seconds forever.

    v0.1.77 (2026-07-24)¶

    Features¶

    • Light theme. Light, dark and follow-system appearances, switchable in settings. The editor, chat code blocks and project visualisation SVGs all follow; the dark appearance is unchanged.
    • Serial dashboard. Data visualisation for MCU serial debugging: waveform data is parsed live from the raw byte stream, with built-in support for common protocols (FireWater, JustFloat) and auto-detection. Waveform, numeric, gauge, LED, button and slider widgets can be arranged by hand — or you can ask the AI to build the whole panel from what your firmware prints.

    v0.1.75 (2026-07-23)¶

    Fixes¶

    • Fixed intermittent "ticket exchange failed" errors for new users on the packaged build. The AI runtime no longer starts on the backend's critical path; a momentary hiccup there can't drag down the whole backend and take sign-in and account endpoints with it. The backend and its health endpoint come up immediately, and the AI side retries in the background or loads lazily. Ticket exchange gained backoff retries and a longer timeout to cover the window right after startup. When the AI runtime exits unexpectedly, the real reason is now written to the backend log.
    • The reasoning-depth menu now scrolls instead of clipping the last options.

    v0.1.74 (2026-07-22)¶

    Fixes¶

    • Built-in, GLM and custom models no longer raise a "model metadata not found" runtime warning. Tool definitions are still delivered, the per-turn fallback warning is gone, and long conversations are no longer truncated below the real context limit. Routing and billing are unchanged.
