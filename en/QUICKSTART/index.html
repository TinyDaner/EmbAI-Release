    Quick Start¶

    From nothing to a successful flash. About 20 minutes, most of it spent waiting for Keil and the firmware library to download.

    1. Install the two things EmbAI does not bundle¶

    Required Why
    Keil MDK Firmware is compiled only by Keil's UV4.exe. EmbAI ships no compiler.
    J-Link drivers The default flash and debug path. For ST-Link or DAPLink see Install & Setup.

    You also need internet access the first time you create a project — the HAL/CMSIS firmware library is fetched from the STM32Cube repositories on GitHub.

    Installation and troubleshooting: Install & Setup.

    2. Install EmbAI and sign in¶

    1. Download the Windows installer from the Releases page, install and launch.
    2. The sign-in screen has exactly one button: Sign in / Register via browser. It opens your system browser; once you finish signing up or signing in there, you are returned to the app automatically.

    Why the browser

    Accounts, AI quota and credits are managed centrally in the cloud. Going through the browser lets you reuse an existing GitHub / Google / WeChat session and keeps password fields out of the app. See Account & Credits.

    3. Confirm your environment¶

    Settings (gear icon, top right) → Compiler → Open environment detection.

    Keil and J-Link should both show as installed. If either is flagged, use Configure path on that row and point it at UV4.exe or JLinkARM.dll.

    Don't skip this

    If Keil is not configured you will not find out until you press Build: 未找到 Keil UV4.exe。请在「环境检测」中配置 Keil 路径……

    4. Create a project¶

    Click New project on the welcome screen (or New in the toolbar) and work through the 6 steps:

    Step What you choose
    1. Chip Filter by series or search a part number — 787 STM32 parts
    2. Firmware library HAL / LL / HAL+LL / SPL, optionally pinning a Cube package version
    3. RTOS Bare metal / FreeRTOS / RT-Thread / CMSIS-RTOS
    4. Peripherals & middleware UART, SPI, I²C, TIM, ADC, DMA, configured individually
    5. Toolchain & probe Defaults to Keil + J-Link + SWD + 4000 kHz
    6. Name & location Plus sample code, Git init, unit tests, Doxygen

    When the wizard finishes, don't build yet: watch the status bar. The firmware library is downloading from GitHub and the project is not ready until that progress bar completes. If it fails, the status bar offers a Retry button.

    Building before the library is down

    The build is blocked with a message saying the firmware library is not ready. That is deliberate — it stops you from compiling against missing HAL headers.

    5. Let the AI write the firmware¶

    The wizard only produces a skeleton that compiles. Once the project exists, the AI panel opens by itself and starts asking what the firmware should do (which LED, which UART, what baud rate), then generates the code one file at a time.

    This is the intended workflow — you are not meant to start from an empty main.c.

    To see its intent before it acts, turn on Plan mode (+ to the left of the input → Plan mode, or Ctrl+Alt+P): the AI submits a plan for approval before touching anything.

    6. Build¶

    Press Build in the toolbar. The bottom panel switches to Build output and streams Keil's log, ending in N Error(s), M Warning(s).

    If it fails, just tell the AI to fix the build errors — it can read that output.

    7. Connect a board and flash¶

    With the probe connected, press Build & flash. A progress dialog walks through erase → program → verify.

    • If the probe is not connected yet, EmbAI connects automatically using the chip from the project configuration.
    • 未找到固件，请先构建项目 means nothing has been built successfully yet.
    • 自动连接失败 usually means no power, a locked debug port, or the wrong interface/speed.

    On success the dialog offers Open serial port, which takes you straight to the next step.

    8. Look at the output¶

    Bottom panel → Serial terminal, pick the port and baud rate, connect. HEX view, timestamps and RX/TX byte counters are all available.

    If your firmware streams numbers rather than text, try Serial Dashboard in the activity bar — a few waveforms and gauges beat staring at a screen of digits. See Serial & Dashboard.

    Common sticking points¶

    Symptom Cause and fix
    Build says it can't find UV4.exe Keil missing or unconfigured. Settings → Compiler → Open environment detection → Configure path
    "Please open a project first" No project is open — create or open one
    Firmware library not ready Wait for the status-bar progress; on failure press Retry
    Firmware library never downloads Requires GitHub access. Fix networking or set a proxy, then retry
    Flashing reports auto-connect failure Check power and wiring; try JTAG instead of SWD, or a lower speed
    GCC / CMake paths set under Compiler do nothing Firmware builds only use Keil; those entries do not affect it
