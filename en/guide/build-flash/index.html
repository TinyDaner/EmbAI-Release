    Build & Flash¶

    Building¶

    Press Build in the toolbar. In order:

    1. All unsaved tabs are saved automatically
    2. The bottom panel switches to Build output
    3. Keil's UV4.exe compiles the project
    4. The log streams in live, ending with N Error(s), M Warning(s)

    Clean rebuild deletes the build/ directory first and compiles from scratch — useful when you suspect the incremental build.

    Why Keil only

    Projects EmbAI creates or imports are ordinary Keil projects (.uvprojx), and building hands off to UV4.exe. The output is therefore identical to compiling by hand in Keil, and colleagues without EmbAI can still open the project.

    Two reasons a build is refused¶

    Message Meaning
    请先打开项目 No project is currently open
    Firmware library not ready HAL/CMSIS is still downloading. Wait, or press Retry in the status bar

    Compiler not found¶

    未找到 Keil UV4.exe。请在「环境检测」中配置 Keil 路径，
或设置 KEIL_PATH 环境变量 / 在 .embai/config.json 写入 keil_path。

    See Install & Setup.

    When the build fails¶

    The AI can read the build output directly. Say "fix the build errors" in the AI panel and it will read the log, locate the file and propose a fix.

    Flashing¶

    With the probe and board connected, press Flash (existing firmware) or Build & flash (compile first).

    A progress dialog walks through erase → program → verify. On success it offers an Open serial port button so you can go straight to the output.

    Automatic connection¶

    If the probe isn't connected yet, EmbAI connects once automatically:

    • Target comes from the project's chip setting
    • Interface defaults to SWD, speed to 4000 kHz

    Common failures¶

    Message Cause
    未找到固件，请先构建项目 Nothing has been built successfully yet
    自动连接失败: … No power, wrong wiring, locked debug port, or unsuitable interface/speed

    J-Link's interface, speed and reset type can be changed from the J-Link indicator in the toolbar.

    The four flashing paths¶

    The default. Requires the SEGGER driver pack. Progress is reported per phase.

    Driven through OpenOCD, which must be on your PATH. Covers F0/F1/F2/F3/F4/F7/G0/G4/H7/ L0/L1/L4/L5/U5/WB/WL.

    Not available in release builds — the pyocd package it depends on is not shipped with the installer, so connecting fails with pyocd not available. See Install & Setup.

    The fallback when there is no debug probe: flashing over the serial bootloader.

    The probe type can only be chosen in step 5 of the new-project wizard; there is no way to change it from inside the application afterwards, and the J-Link indicator in the toolbar opens J-Link's own parameters.

    Flashing and debugging always go through J-Link today

    The probe chosen in the wizard only affects the generated project configuration. To flash over ST-Link or DAPLink, use those vendors' own tools for the time being.

    Map file analysis¶

    Activity bar → Build analysis → Map file analysis.

    Parses the map file produced by the build and breaks Flash and RAM usage down by module and symbol — for answering "what exactly is eating my memory".

    Working with the AI¶

    All of these can just be asked for:

    • "compile this" / "clean rebuild"
    • "build and flash it to the board"
    • "how much Flash are we using now"

    Whether the AI has to ask permission first depends on the approval mode.
