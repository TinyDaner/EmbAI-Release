    Debugging¶

    Activity bar → Core → Debug.

    Layout¶

    Area Contents
    Top toolbar Start / Continue / Pause / Stop / Step in / Step over / Step out / Reset, plus settings entry points
    Left column Project files, variable watch, breakpoint list, call stack, power control
    Centre Source view — click the gutter to set breakpoints; the current line is marked

    Starting and stopping¶

    With the board connected and firmware flashed, press Start debugging.

    While disconnected the toolbar also offers a Hot Plug checkbox, for attaching to an already-running target without resetting it.

    Once connected the toolbar switches to run control:

    Button Effect
    Continue Run at full speed from the current position
    Pause Halt at the current PC
    Step in / over / out Single-step into a call, across it, or out to the caller
    Reset Reset the target
    Stop End the debug session

    Breakpoints¶

    • Set one: click the gutter to the left of the source
    • Breakpoint list: the left column lists them all; click the dot on a row to enable/disable
    • Delete / edit: use the toolbar's Breakpoints / Watchpoints panel to delete, set conditions and see hit counts; clicking the same gutter line again also removes the breakpoint
    • Watchpoints: set data breakpoints from the breakpoint manager to halt on variable access

    Inspecting state¶

    The Variables panel shows the locals of the function you are halted in (name / value / type), refreshed on every halt or step. Custom watch expressions are not supported yet — use expression evaluation in the toolbar for globals or a specific address.

    The call chain when halted (function name + file:line), current frame at the top.

    Read-only for now: clicking a frame does not jump to the source, and the variables panel always shows the frame at the current PC — you cannot switch to a caller's variables yet.

    Live core register values.

    There is no dedicated memory panel. To read memory by address, use the toolbar's command window and type mem read <addr> [<len>] (16 bytes if the length is omitted) — handy for peripheral registers or buffers.

    The command window only allows reads; memory-write commands are rejected by an allow-list.

    The expression panel evaluates an expression ad hoc — global variable names (once symbols are loaded) and 0x hex addresses are supported.

    Disassembly and symbols¶

    Disassembly is available, as is jumping to a symbol's definition from the toolbar's symbol navigation entry.

    Target power control¶

    The left column can turn target power on, off, or power-cycle it on probes that support it — a way to reset the supply without unplugging anything.

    Debug commands¶

    The command window in the toolbar lets you issue debug commands directly, which covers operations that have no dedicated button.

    Saving and restoring a session¶

    Debug configuration (breakpoints, watchpoints, Monitor mode) can be saved and restored, so you don't have to set everything up again next time.

    Monitor mode¶

    The Monitor mode dialog in the toolbar switches between two ways of halting on a breakpoint: in Halt mode the CPU stops completely (the standard behaviour); in Monitor mode only the application thread is paused while interrupts and DMA keep running, which suits motor control and communication protocols. Not every Cortex-M part and probe supports Monitor mode.

    Note

    Switches labelled as UI placeholders in that dialog currently have no effect.

    RTT log¶

    The RTT log tab in the bottom panel receives SEGGER RTT output — useful for logging without occupying a UART.

    Working with the AI¶

    The AI has the full set of debug control tools, so you can simply say:

    • "set a breakpoint at line 120 of main.c and start debugging"
    • "what's adc_value right now"
    • "read 32 bytes starting at 0x40020000"

    Whether hardware operations require your confirmation depends on the approval mode.
