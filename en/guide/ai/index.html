    AI Assistant¶

    A docked panel on the right, toggled with Ctrl+J. Switching views does not interrupt the conversation.

    It is not just a chat box: around 130 tools let it genuinely read and write files, build and flash, set breakpoints and step, read registers, configure pins and query Git.

    Choosing a model¶

    Settings → AI models, in two groups:

    Built-in¶

    Works out of the box, no API key needed. Runs through the EmbAI cloud and is billed in credits; each model shows its price (e.g. 0.9 / 2.7, input and output respectively).

    For how credits work, see Account & Credits.

    Your own models¶

    Supply your own endpoint and API key. These go directly to the vendor and consume no EmbAI credits.

    Supported vendors: Anthropic, OpenAI, Qwen, Zhipu GLM, MiniMax, Kimi (Moonshot), DeepSeek, and custom. The wire format can be responses, chat_completions or anthropic_messages.

    API keys are stored encrypted, per account.

    You can have both

    Use the built-in models for convenience day to day, and switch to your own key for long runs. The model picker sits in the toolbar below the input box (left of the send button, showing the current model name), not at the top of the panel.

    Plan mode¶

    Makes the AI submit a plan and wait for approval before acting. Worth it whenever the change is broad and you don't want it charging ahead.

    Three ways to turn it on:

    • + to the left of the input → Plan mode
    • Type /plan <your task>
    • Ctrl+Alt+P

    The input box then shows a blue outline and a lightbulb marker.

    The AI produces a Markdown plan card, and you can:

    Action Effect
    Approve Start executing the plan
    Request changes Send your comments back and have the plan revised
    Reject Turn the plan down
    Cancel Abort

    The card's status follows execution (in progress, completed, incomplete, and so on).

    ⋯ in the panel header → Plan history and templates lets you review past plans, save good ones as reusable templates, and take checkpoints or roll back.

    Approval modes¶

    The shield icon above the input decides when the AI must ask before acting:

    Mode Behaviour
    Ask for approval File writes and risky operations always prompt
    Approve for me (default) Only operations judged risky prompt
    Full access Never prompts; may edit project files and flash directly (switching asks for confirmation)

    Settings → AI models also has per-category tool switches: file operations, build, debug control, memory, trace analysis, hardware control, MCU configuration (peripheral and register access belongs here), SDK management, virtual hardware, toolchain, schematics, datasheets and promote-to-hardware, plus a few that are not localised yet and show their raw key (standard / knowledge / search / symbol / git / dashboard). Turning a category off removes those tools entirely.

    The list is served dynamically by the backend, so new categories appear automatically.

    Giving the AI context¶

    Attachments¶

    + to the left of the input → Add:

    • File — pick from the project tree
    • Selected code — whatever is selected in the editor
    • Build errors — attach the errors from the build output directly
    • Image — screenshots, photos of the board, scope captures

    @ references¶

    Typing @ triggers completion:

    • @schematic:filename — reference an analysed schematic
    • @datasheet:filename — reference an indexed datasheet

    For example: "initialise SPI2 the way @schematic:mainboard-v2 wires it".

    Slash commands¶

    Command Purpose
    /plan <task> Start in Plan mode
    /template Use a plan template
    /explain Explain the selected or named code
    /fix Fix a problem
    /build Ask the AI to review the build configuration (not the same as the toolbar's Build)
    /flash Flash
    /register <name> Look up a register
    /peripheral <name> Look up a peripheral
    /hal <name> Generate HAL driver code for that peripheral

    When the AI asks you¶

    When a requirement is ambiguous the AI asks, offering two to four options to pick from rather than guessing. Code generation after project creation leans on this heavily — it walks through your requirements one item at a time.

    Session management¶

    Action How
    New session Ctrl+L
    Stop the current answer Esc
    Focus the input Ctrl+K
    Archive / restore Toggle show-archived-tasks at the bottom of the session list
    Fork Copy the task from its current progress into a new thread; the original is kept in full (you cannot pick a past message as the fork point)
    Rewind Return to an earlier state and retry
    Compact context Summarise earlier turns to free up context
    Copy as Markdown Export the whole conversation

    Conversations keep running in the background — closing the panel or switching views does not interrupt them, and the full transcript is there when you come back.

    Web search¶

    The AI can only search the web once you configure a search provider and key under Settings → AI models → Web search. Without it, it simply doesn't go online; nothing else is affected.

    Suggestions¶

    • Use Plan mode for anything large — reading a plan is cheaper than rolling back
    • Hand it errors directly — + → Build errors beats paraphrasing them
    • Upload the schematic first — every later pin-related conversation gets shorter
    • Keep an eye on credits during long runs — built-in models bill per token, see Account & Credits
