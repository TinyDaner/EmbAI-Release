    Install & Setup¶

    EmbAI currently ships for Windows 10 / 11 (64-bit) only.

    Installing EmbAI itself is not enough — building and flashing depend on two third-party tools you have to install yourself.

    Overview¶

    Required? Used for
    EmbAI installer Yes The application
    Keil MDK Yes The only firmware toolchain
    J-Link drivers Yes Flashing and debugging always go through J-Link — see section 3
    GitHub access Yes, for the first project Downloading the HAL/CMSIS firmware library
    OpenOCD Optional Needed when flashing over ST-Link
    CMake + GCC Optional Only used by the Virtual Display

    1. Install EmbAI¶

    Download the installer from the Releases page and run it.

    You don't need to download later versions manually: click the version number at the top left of the app → Check for updates to download and install in place.

    2. Install Keil MDK¶

    Download MDK from the Arm Keil site and follow their instructions for installation and licensing.

    EmbAI looks for UV4.exe in this order and uses the first hit:

    1. keil_path in the project's .embai/config.json
    2. The Keil path stored in application settings (Settings → Compiler)
    3. The KEIL_PATH environment variable
    4. Default install locations C:\Keil_v5\UV4\UV4.exe and C:\Keil\UV4\UV4.exe
    5. The registry and PATH

    A default installation normally needs no configuration at all.

    Build says UV4.exe was not found

    未找到 Keil UV4.exe。请在「环境检测」中配置 Keil 路径，
或设置 KEIL_PATH 环境变量 / 在 .embai/config.json 写入 keil_path。
    Set the path manually as described in section 4.

    3. Install probe drivers¶

    Install SEGGER's J-Link Software and Documentation Pack. EmbAI talks to the probe through its JLinkARM.dll.

    Afterwards the J-Link indicator in the toolbar should detect your probe. If it doesn't, you can point EmbAI at the DLL manually from environment detection.

    The ST-Link path requires OpenOCD. Install it yourself and make sure openocd is on your PATH.

    Target series covered: F0 / F1 / F2 / F3 / F4 / F7 / G0 / G4 / H7 / L0 / L1 / L4 / L5 / U5 / WB / WL.

    Not available in release builds

    This path depends on the Python pyocd package, which is not shipped with the installer (it is in neither backend/requirements.txt nor the packaging spec). The new-project wizard lets you select DAPLink, but connecting fails immediately with pyocd not available.

    The released backend is a frozen bundle with its own interpreter, so pip install pyocd into your system Python does not help either. Use J-Link or ST-Link for now.

    With no debug probe at all, some parts can be flashed over the serial bootloader (BOOT0 pulled high).

    The probe type can only be chosen in step 5 of the new-project wizard, which writes it to .embai/config.json; there is no way to change it from inside the application afterwards. The J-Link indicator in the toolbar opens J-Link settings — interface, speed, reset type and other J-Link-specific parameters — not a probe-type selector.

    Flashing and debugging always go through J-Link today

    The probe chosen in step 5 currently only affects the generated project configuration; EmbAI's own flash/debug path always uses the J-Link backend. To flash over ST-Link or DAPLink, use those vendors' own tools for the time being.

    4. Environment detection¶

    Settings (gear icon, top right) → Compiler → Open environment detection.

    This dialog probes for Keil, J-Link, ARM GCC, CMake, Ninja, OpenOCD, Python and Git, and marks whether the required ones are present. The Keil and J-Link rows have a Configure path button that lets you point at UV4.exe / JLinkARM.dll directly; the choice is saved immediately.

    The GCC and CMake paths on the Compiler page do not affect firmware builds

    Firmware is compiled by Keil only. Those two entries currently play no part in it.

    5. Networking: the first project downloads a firmware library¶

    When you create a project, EmbAI fetches the matching HAL/CMSIS sources for your chip series from the STM32Cube repositories on GitHub. This runs in the background with progress in the status bar.

    • Building before it finishes is blocked with a "firmware library not ready" message — just wait.
    • On failure the status bar shows Retry and Ignore.
    • On networks where GitHub is slow or blocked, configure a proxy before creating a project.

    6. Optional: the virtual display toolchain¶

    The Virtual Display compiles and runs your driver code natively on your PC, so it needs a host CMake and GCC — not a cross toolchain.

    When they are missing, /virtual/build returns HTTP 424 and a banner appears in that view.

    Install the toolchain manually rather than relying on the one-click button

    The one-click installer downloads and unpacks a toolchain, but its bundled checksums are placeholders, so integrity verification is skipped entirely — whatever is downloaded gets installed unverified. Install CMake and MinGW-w64 / LLVM-mingw yourself, add them to PATH, and reopen the view.

    7. Where files live¶

    Location Contents
    <project>\.embai\ Per-project configuration (config.json), dashboard layout (dashboard.json)
    %USERPROFILE%\.embai\ Local database, firmware-pack / Pack / toolchain caches, file history, uploads, and the crash log embai_crash.log
    %APPDATA%\EmbAI\ The desktop runtime log backend.log. This is what Help & feedback attaches

    Troubleshooting¶

    Symptom What to do
    Blank window or stuck splash after install Give it a few seconds, then restart. If it persists, use Help & Feedback — logs are attached automatically
    Build can't find UV4.exe See section 2
    J-Link indicator stays grey Check the SEGGER driver pack is installed, that the USB cable carries data, and that the board is powered
    ST-Link doesn't work Make sure openocd is on your PATH
    Firmware library download keeps failing Requires GitHub access; set a proxy and press Retry in the status bar
    Virtual display reports a missing toolchain Install CMake + GCC onto PATH, see section 6
