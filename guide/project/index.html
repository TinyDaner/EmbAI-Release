    工程管理¶

    新建工程¶

    入口：欢迎页的新建项目，或工具栏的新建。

    向导共 6 步：

    1. 选芯片¶

    按系列筛选，或直接搜型号。收录 18 个 STM32 系列共 787 颗。

    2. 固件库¶

    选项 说明
    HAL ST 的硬件抽象层，上手快、代码量大
    LL 底层库，接近寄存器、开销小
    HAL + LL 两者并存，按外设各取所需
    SPL 标准外设库，老工程沿用

    可以指定 Cube 固件包版本；不指定则用推荐版本。

    3. RTOS¶

    裸机 / FreeRTOS / RT-Thread / CMSIS-RTOS。选了 RTOS 之后可以继续配置堆大小、 tick 频率、内存管理方案和优先级数量。

    4. 外设与中间件¶

    UART、SPI、I²C、TIM、ADC、DMA 逐项展开配置。这一步选的外设会影响生成的初始化代码。

    5. 工具链与调试器¶

    默认 Keil MDK + J-Link + SWD + 4000 kHz。固件编译目前只支持 Keil。

    6. 名称与路径¶

    填工程名和存放目录，再勾选：示例代码、Git 初始化（默认开）、单元测试脚手架、Doxygen 注释。

    没装 Git 的话

    勾了「Git 初始化」但机器上没有 Git，这一步会静默跳过，不影响工程创建。

    建完之后：等库，然后交给 AI¶

    点完成后有两件事在跑：

    一、固件库下载。 EmbAI 从 GitHub 上的 STM32Cube 仓库拉取对应版本的 HAL/CMSIS 源码， 进度显示在状态栏。没下完不能编译 —— 强行构建会被拦下并提示固件库尚未就绪。 失败时状态栏会给出重试按钮。

    二、AI 接管业务代码。 向导只生成「能编译的工程基座」。工程建好后 AI 面板自动打开， 开始逐项反问你的需求，然后按规范一个文件一个文件地生成代码。

    这是 EmbAI 设计上的主线：向导负责骨架，AI 负责血肉。你不需要从空的 main.c 开始。

    生成结构因芯片而异

    STM32H743 系列使用固定的 Keil 分层骨架（ARM/ App/ HW/ FW/ Drivers/ Project）。 其他型号走代码生成，产物结构不同，但同样是可直接编译的 Keil 工程。

    打开已有工程¶

    欢迎页的打开项目，或工具栏工程名下拉里的选项。选择工程根目录即可。 下拉里也可以直接输入路径打开。

    迁移已有的 Keil 工程¶

    把手头的 .uvprojx 工程接进 EmbAI：工具栏工程名下拉 → 迁移 / 接入 Keil 工程。

    向导 5 步：

    1. 检测 —— 扫描工程结构、芯片型号、固件库、包含路径。这一步只读，不写盘
    2. 确认 —— 核对识别结果，不对的可以改
    3. 补库 —— 缺失的 HAL/CMSIS 按需补齐
    4. 试编译 —— 先编一次，确认接进来之后还能正常构建
    5. 完成

    迁移完成后 AI 会主动介绍这个工程的结构，方便你直接开始提需求。

    最近工程¶

    欢迎页列出最近打开过的工程，支持搜索、排序、移除。上次打开的工程会在下次启动时 自动恢复，连同当时打开的编辑器标签页。

    工程配置文件¶

    每个工程根目录下有一个 .embai/ 目录，其中 config.json 记录了向导选择的结果：

    字段 含义
    chip / series 芯片型号与系列
    name 工程名
    firmware_lib 固件库（hal / ll / hal-ll / spl）
    toolchain 工具链，当前恒为 keil-mdk
    debugger 调试器
    rtos / middleware RTOS 与中间件选择
    peripherals 外设配置
    layout 工程布局类型
    keil_path 可选，覆盖本工程使用的 UV4.exe 路径

    这个文件可以进版本库 —— 同事拉下来就是同一套配置。

    让新工程遵循团队规范¶

    如果你在公司规范里上传并启用了一份代码规范， 新建工程时 AI 会按那份规范来组织目录、文件头、命名和外设初始化顺序。
