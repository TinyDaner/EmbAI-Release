    虚拟显示屏¶

    活动栏 → 虚拟与原理图 → 虚拟显示。

    调 OLED / TFT 界面最烦的是「改一行、编译、烧录、看一眼、再改一行」。虚拟显示屏把这个 循环压缩成几秒：你的驱动代码在本机编译并运行，它往 SPI/I²C 上写的命令字节被截获， 按真实控制器的时序还原成画面，直接渲染在界面上。

    不需要板子，不需要烧录。

    前置条件¶

    需要主机端的 CMake 和 GCC（注意：不是 arm 交叉编译工具链，是本机原生编译器）。

    缺失时视图顶部会出现提示横幅。

    建议手动安装工具链

    横幅上的一键安装会下载并解压工具链，但内置校验和是占位值，完整性校验会被整个跳过 —— 也就是说下载内容不经任何验证就直接安装。 请自行安装 CMake 与 MinGW-w64 / LLVM-mingw 并加入 PATH，然后重开该视图。

    支持的屏¶

    共 22 种型号，涵盖单色 OLED、彩色 TFT、圆屏和 AMOLED：

    类别 型号
    单色 OLED SSD1306（I²C / SPI）、SH1106
    彩色 TFT ST7789（240×240 / 240×320 / 240×280 / 135×240）、ILI9341、ST7735（128×160 / 128×128）、ILI9488、ST7796、SSD1351
    圆屏 GC9A01、CO5300（360 / 466）、SH8601（454 / 368×448）
    其他 RM67162、SSD1963（800×480 / 480×272）、NT35510

    在顶部下拉里选型号，画布会按该屏的分辨率和形状渲染。

    怎么用¶

    1. 把驱动和界面代码放到工程的 virtual_ui/ 目录（没有的话会回退到根目录的 virtual_main.c）
    2. 顶部选好屏型号
    3. 点编译并运行
    4. 画面出现在画布上；底部的编译 / 运行日志可以看输出

    顶部还有停止、重置、截图，以及 1× / 2× / 4× / 8× 缩放。

    模拟输入¶

    右栏可以往运行中的程序注入输入：

    面板 作用
    按钮 模拟按键按下/抬起
    电位器 拖滑杆注入 ADC 电压值
    串口监视 看程序打印到虚拟 UART 的输出（只读，暂不支持往里发数据）

    打开顶部的鼠标触摸开关后，在画布上点击会被当作触摸事件注入 —— 触摸屏 UI 可以直接试。

    提升到硬件¶

    界面调好之后，点顶部的提升到硬件把虚拟工程转成真实固件代码。

    流程是两步：

    1. 预览 —— 先做一次演练，列出将要新增/修改的文件、引脚映射、总线映射和警告， 你逐项勾选要采纳哪些
    2. 应用 —— 确认后才真正写盘

    如果目标文件你手工改过，会被识别为冲突并提示，不会默默覆盖；确实要覆盖时可以显式勾选。

    与 AI 配合¶

    AI 可以直接开关虚拟运行、截图看当前画面、注入按钮和 ADC、读虚拟串口。 所以你可以说：

    • 「跑一下虚拟屏，截图看看现在什么样」
    • 「把电位器调到 1.5V，再截一张」
    • 「主界面居中显示不对，你自己跑起来看看再改」

    这条路径的价值在于 AI 能看到自己写的 UI 效果并自行迭代，不用你每次充当它的眼睛。
