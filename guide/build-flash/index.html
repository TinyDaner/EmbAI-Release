    编译与烧录¶

    编译¶

    工具栏点构建。

    发生的事情按顺序是：

    1. 自动保存所有未保存的标签页
    2. 底部面板切到构建输出
    3. 调用 Keil 的 UV4.exe 编译工程
    4. 日志实时刷进构建输出，最后一行是 N Error(s), M Warning(s)

    清理重建：先删掉 build/ 目录再完整编译一遍，用于怀疑增量编译出问题的时候。

    为什么只支持 Keil

    EmbAI 生成和迁移的都是标准 Keil 工程（.uvprojx），编译直接交给 UV4.exe。 这样产物和你在 Keil 里手工编译的完全一致，团队里没装 EmbAI 的同事也能正常打开。

    构建被拦下的两种情况¶

    提示 含义
    请先打开项目 当前没有打开的工程
    固件库尚未就绪 HAL/CMSIS 还在下载。等状态栏进度条走完，或点重试

    找不到编译器¶

    未找到 Keil UV4.exe。请在「环境检测」中配置 Keil 路径，
或设置 KEIL_PATH 环境变量 / 在 .embai/config.json 写入 keil_path。

    见安装与环境。

    编译报错怎么办¶

    构建输出里的错误 AI 是能直接读到的。在 AI 面板里说一句「修一下编译错误」， 它会去看日志、定位文件、给出改法。

    烧录¶

    接好调试器和板子，工具栏点烧录（只烧现有固件）或构建并烧录（先编译再烧）。

    会弹出进度对话框，依次经过擦除 → 写入 → 校验三个阶段。烧录成功后的对话框上有 打开串口按钮，可以直接去看输出。

    自动连接¶

    如果调试器还没连上，EmbAI 会自动连接一次：

    • 目标芯片取自工程配置里的 chip
    • 接口默认 SWD，速率默认 4000 kHz

    常见失败¶

    提示 原因
    未找到固件，请先构建项目 还没成功编译过
    自动连接失败: … 板子没供电、接线不对、调试口被锁，或接口/速率不合适

    J-Link 的接口、速度、复位类型等参数可以在工具栏的 J-Link 状态灯里改。

    四种烧录路径¶

    默认路径，需要装 SEGGER 驱动包。烧录进度按阶段实时回报。

    经 OpenOCD 驱动，需要 openocd 在 PATH 上。覆盖 F0/F1/F2/F3/F4/F7/G0/G4/H7/ L0/L1/L4/L5/U5/WB/WL 系列。

    正式版暂不可用 —— 依赖的 pyocd 没有随安装包分发，连接时会直接报 pyocd not available。详见安装与环境。

    没有调试器时的退路，通过串口进 bootloader 烧录。

    调试器类型只能在新建工程向导第 5 步选定，工程建好后应用内没有切换入口；工具栏 J-Link 状态灯打开的是 J-Link 自身的参数设置。

    烧录与调试链路目前固定走 J-Link

    向导里选的调试器只影响生成的工程模板配置。要用 ST-Link / DAPLink 烧录， 请暂时借助它们各自的官方工具。

    Map 文件分析¶

    活动栏 → 编译分析 → Map 文件分析。

    解析编译产生的 map 文件，按模块和符号展示 Flash / RAM 占用，用来回答「到底谁把空间吃光了」。

    与 AI 配合¶

    以下都可以直接说，不用自己点按钮：

    • 「编译一下」「清理重新编译」
    • 「编译并烧录到板子上」
    • 「看看现在 Flash 占用多少」

    AI 调用这些操作时，是否需要先征求你同意，取决于审批模式的设置。
