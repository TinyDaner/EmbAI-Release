    安装与环境¶

    EmbAI 目前只发行 Windows 10 / 11（64 位） 版本。

    装完 EmbAI 本身还不够 —— 编译和烧录依赖两个第三方工具，需要你自己安装。

    一览¶

    必需性 用途
    EmbAI 安装包 必需 应用本体
    Keil MDK 必需 唯一的固件编译工具链
    J-Link 驱动 必需 烧录与调试链路固定走 J-Link，见第 3 节
    能访问 GitHub 的网络 首次建工程必需 下载 HAL/CMSIS 固件库
    OpenOCD 可选 用 ST-Link 烧录时需要
    CMake + GCC 可选 只有虚拟显示屏用得到

    1. 安装 EmbAI¶

    从 Releases 页面下载安装包， 双击安装即可。

    后续版本不用重新下载：应用内点左上角版本号 → 检查更新，可以直接下载并安装新版本。

    2. 安装 Keil MDK¶

    从 Arm Keil 官网下载 MDK 并按官方说明完成安装与授权。

    EmbAI 按以下顺序找 UV4.exe，命中任意一条即可：

    1. 工程目录下 .embai/config.json 里的 keil_path
    2. 应用设置里的 Keil 路径（设置 → 编译器）
    3. KEIL_PATH 环境变量
    4. 默认安装位置 C:\Keil_v5\UV4\UV4.exe 或 C:\Keil\UV4\UV4.exe
    5. 注册表与 PATH

    装在默认位置的话通常什么都不用配。

    点「构建」时提示找不到 UV4.exe

    未找到 Keil UV4.exe。请在「环境检测」中配置 Keil 路径，
或设置 KEIL_PATH 环境变量 / 在 .embai/config.json 写入 keil_path。
    按第 4 节手动指定路径即可。

    3. 安装调试器驱动¶

    装 SEGGER 官网的 J-Link Software and Documentation Pack。EmbAI 通过其中的 JLinkARM.dll 与调试器通信。

    装完后工具栏右侧的 J-Link 状态灯应该能识别到设备。识别不到时同样可以在环境检测里 手动指定 DLL 路径。

    ST-Link 路径依赖 OpenOCD，请自行安装并确保 openocd 在 PATH 上。

    覆盖的目标系列：F0 / F1 / F2 / F3 / F4 / F7 / G0 / G4 / H7 / L0 / L1 / L4 / L5 / U5 / WB / WL。

    正式版暂不可用

    这条通路依赖 Python 的 pyocd 库，而 pyocd 没有随安装包分发 （既不在 backend/requirements.txt，也不在打包脚本里）。新建工程向导里虽然 能选到 DAPLink，但连接时会直接报 pyocd not available。

    发布版后端是自带解释器的冻结包，在系统 Python 里 pip install pyocd 也不生效。 目前请改用 J-Link 或 ST-Link。

    没有调试器时，部分型号可以走串口 ISP 烧录（BOOT0 拉高进 bootloader）。

    调试器类型只能在新建工程向导的第 5 步选，选完写进 .embai/config.json；工程建好后 应用内没有切换调试器类型的入口。工具栏 J-Link 状态灯点开的是「J-Link 设置」， 里面是接口、速度、复位类型等 J-Link 专属参数，不能在这里换调试器类型。

    当前烧录与调试链路固定走 J-Link

    向导第 5 步选的调试器目前只影响生成的工程模板配置，EmbAI 自己的烧录/调试始终使用 J-Link 后端。要用 ST-Link / DAPLink 烧录，请暂时借助它们各自的官方工具。

    4. 环境检测¶

    设置（右上角齿轮）→ 编译器 → 打开环境检测。

    这个对话框会逐项探测 Keil、J-Link、ARM GCC、CMake、Ninja、OpenOCD、Python、Git， 并标出必需项是否就绪。Keil 和 J-Link 两行右侧有配置路径按钮，可以手动指到 UV4.exe / JLinkARM.dll，选完立即保存。

    「编译器」页里的 GCC 与 CMake 路径不影响固件编译

    固件编译只走 Keil。这两项当前不参与固件构建，填了也不会改变编译行为。

    5. 网络：首次建工程要下固件库¶

    新建工程时，EmbAI 会按你选的芯片系列从 GitHub 上的 STM32Cube 仓库拉取对应版本的 HAL/CMSIS 源码。这一步在后台进行，进度显示在状态栏。

    • 没下完就点构建，会被拦下并提示固件库尚未就绪 —— 等进度条走完即可。
    • 下载失败时状态栏会出现重试和忽略两个按钮。
    • 访问 GitHub 不畅的网络环境下，建议先配好代理再建工程。

    6. 可选：虚拟显示屏的工具链¶

    虚拟显示屏是在本机原生编译并运行你的驱动代码， 因此需要主机端的 CMake 和 GCC（不是交叉编译工具链）。

    缺失时 /virtual/build 会返回 HTTP 424，界面上显示一条提示横幅。

    推荐手动安装，别依赖「一键安装」

    横幅上的一键安装会下载并解压工具链，但内置校验和是占位值，完整性校验会被整个跳过 —— 也就是说下载内容不经任何验证就直接安装。 请自行安装 CMake 与 MinGW-w64 / LLVM-mingw 并加入 PATH，然后重开该视图。

    7. 文件都放在哪¶

    位置 内容
    <工程目录>\.embai\ 该工程的配置（config.json）、仪表盘布局（dashboard.json）等
    %USERPROFILE%\.embai\ 本机数据库、固件包 / Pack / 工具链缓存、文件历史、上传件，以及崩溃日志 embai_crash.log
    %APPDATA%\EmbAI\ 桌面端运行日志 backend.log。「帮助与反馈」附带的日志尾部取自这里

    常见问题¶

    现象 处理
    装完启动白屏或卡在启动页 等几秒；仍不行就退出重开。持续复现请用「帮助与反馈」上报，会自动附带日志
    构建提示找不到 UV4.exe 见第 2 节
    J-Link 灯一直是灰的 确认装了 SEGGER 驱动包、USB 线是数据线、板子已供电
    ST-Link 用不了 确认 openocd 在 PATH 上
    固件库下载一直失败 需要能访问 GitHub；配好代理后点状态栏的重试
    虚拟显示屏提示缺工具链 手动装 CMake + GCC 到 PATH，见第 6 节
